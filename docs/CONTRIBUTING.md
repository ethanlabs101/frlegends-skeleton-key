# Contributing

Skeleton Key is primarily developed and maintained by its creator.

This project is not intended to operate like a large open-source organization with an open flood of pull requests, feature requests, and unsolicited changes. Contributions are welcome, but they are intentionally kept selective.

## ⭐ Support the Project

You do not need to contribute code to support Skeleton Key.

If you find the project useful, a few simple things help:

- ⭐ Star the repository.
- Follow ethanlabs101.
- Share the project with people who may find it useful.
- Submit useful FR Legends assets to the FR Legends Skeleton Key Asset Database.
- ☕ Buy me a coffee if you want to directly support development.

Stars, follows, and exposure are especially appreciated because they help the project reach more people.

## ☕ Buy Me a Coffee

If Skeleton Key has been useful to you and you would like to support continued development, you can support the project through Buy Me a Coffee.

## 🎨 Asset Contributions

The project has a dedicated asset database for FR Legends cars, liveries, packs, and other community content.

If you have assets you want to contribute, the preferred route is through the asset database rather than submitting them directly to the Skeleton Key source repository.

Please make sure submitted assets are:

- Actually usable.
- Properly categorized.
- Clearly identified.
- Not stolen or knowingly redistributed without permission.
- Accompanied by any attribution or source information that should be preserved.

## 💻 Code Contributions

Code contributions are accepted, but Skeleton Key does **not** use an open pull-request workflow for code contributions.

If you have code, a fix, an optimization, a new module, or another technical improvement you believe belongs in Skeleton Key, send it directly for review by email.

**Code contribution email:** `ethanlabs101@proton.me`

Include:

- What you changed.
- Why you changed it.
- What problem it solves.
- Any relevant files or code.
- How you tested it.
- Any limitations or known issues.

Do not send passwords, PlayFab credentials, authentication tokens, `identity_vault.db`, `.vault.lock`, private account data, or other sensitive information.

Submitting code does not guarantee that it will be used or merged.

Submitted code may be modified, rewritten, rejected, or simply not used depending on the project's needs and direction.

## 📬 Why Not Pull Requests?

This is intentional.

Skeleton Key is a specialized project and its architecture, code quality, dependencies, and overall direction are intentionally maintained by the project creator.

A smaller contribution pipeline also makes it possible to review contributions individually without turning the repository into a queue of pull requests.

If you have something genuinely useful, send it over.

If it fits the project, it can be considered.

## 🧠 Reverse Engineering & Technical Research

Technical findings are welcome when they are backed by actual research, testing, or reproducible observations.

If you are submitting information about:

- Save structures
- Binary formats
- Livery data
- Game objects
- Serialization
- Runtime behavior
- Other FR Legends internals

Please explain how the information was determined whenever possible.

Clear evidence is much more useful than unsupported assumptions.

## 🚫 What Not to Send

Please do not send:

- Stolen credentials.
- Authentication tokens.
- Private account information.
- Other people's personal data.
- Malicious code.
- Deliberately destructive changes.
- Unrelated dependencies or framework rewrites.
- Massive unsolicited refactors.
- Pull requests expecting automatic review or acceptance.

## Final Note

You don't have to write code to contribute.

A useful asset, a bug report, a technical discovery, a repository star, or simply helping another person find the project can all be valuable.

Contributions are appreciated, but Skeleton Key remains a selectively maintained project and its direction ultimately stays with the project maintainer.
